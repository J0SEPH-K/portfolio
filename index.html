Step 01 · Reverse-engineer

레퍼런스를 “읽는” 에이전트

브라우저 에이전트로 레퍼런스 사이트를 직접 스크롤·클릭하고, DOM·스크립트를 분석해 사용 라이브러리와 인터랙션 구조(핀 고정, 스크롤 스크럽, 단어 분할 인트로)를 파악합니다. 이 사이트도 그렇게 시작했습니다.

gsap · ScrollTrigger · Lenis · Barba

Step 02 · Parallelize

10개 에이전트 병렬 개발

GoCreaty 백엔드는 git worktree로 분리된 10개의 Claude Code 에이전트가 각자 레인(DB, API, 파이프라인…)을 맡아 동시에 개발했고, 저는 의존 순서대로 리뷰·머지하며 프론트엔드를 직접 맡았습니다.

tmux · worktree × 10 · merge order

Step 03 · Verify in browser

“동작한다”는 증거로 끝내기

에이전트가 만든 화면은 에이전트가 직접 띄워 확인합니다. 콘솔 에러, 네트워크, 모바일 뷰포트, 실제 클릭까지—스크린샷이 아닌 측정값으로 검증합니다.

preview · console · viewport · a11y

Step 04 · Judgment

만들기 전에 “왜”를 먼저

AI가 빨리 만들수록 잘못된 것을 빨리 만들 위험도 커집니다. 기존 도구로 충분하지 않은지 먼저 검증하고, 그래도 필요할 때 만듭니다. 실제로 프로젝트 하나는 그 판단으로 접었습니다.

validate → build → measure
